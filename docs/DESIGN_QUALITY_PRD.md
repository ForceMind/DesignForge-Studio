# DesignForge Studio｜Design Quality Engine + Auto Polish 需求规格

> 状态：**已纳入研发需求，尚未实现/验收** · 2026-11-02 · 适用 M1 后续质量增强与 M2 AI 工作流  
> 产品：DesignForge Studio（形界设计工作台） · 维护范围：本地优先、结构化设计、可审核的 Agent 局部修改

## 0. 需求来源与决策

- 用户提供的讨论参考：[Bruce Van 的 X 帖子](https://x.com/bruc3van/status/2115963644811116732)。
- 本文记录此前对“高质量 UI 设计、细节规范、中文排版、消除模板化与可编辑 AI 精修”的**产品化吸收**，不把社交媒体个人意见表述成普适标准，也不复制他人的截图、图标、组件或私有提示词。
- 需求决策：**不再仅靠提示词生成漂亮截图，而是让设计质量可检查、问题可定位、修复可审阅、结果可回归。**
- 实现前应复核外部观点与适用性；本规格是本项目的原创产品需求，不是第三方功能或源码的移植记录。
- 配套任务见 [DESIGN_QUALITY_BACKLOG.md](DESIGN_QUALITY_BACKLOG.md)，阶段安排见 [ROADMAP.md](ROADMAP.md)。

## 1. 定位、价值与非目标

**目标**：在现有 DesignForge AST / Token / 组件 / 浏览器测量 / Patch 机制之上形成“设计检查 → 解释 → 局部建议 → 审批 → 前后验证”的闭环。默认保留品牌、人工编辑、布局语义、组件实例与多断点行为。

**面向用户**：独立产品设计师、产品经理、使用 Codex/Claude Code 等 Agent 修改 UI 的开发者，以及移动 App、H5 游戏、游戏 HUD、语聊产品与后台系统设计者。

**非目标**：

1. 不将“紫色、渐变、圆角、某种字体”一律判错，不做审美审查员。
2. 不宣称“识别某个界面是否由 AI 生成”；只能提示具有模板化倾向的可观察特征。
3. 不把自动打分当作客观审美真理，不虚构设计质量提升百分比或 WCAG 认证。
4. 不在用户授权前访问外部模型、上传设计截图、传输完整项目或部署任何页面。
5. 不绕过旧项目格式校验、组件锁、快照哈希、用户确认与已有 Agent Patch 白名单。

## 2. 借鉴方向与产品映射

| 借鉴的设计主题 | DesignForge 应实现的可执行能力 | 判定性质 |
| --- | --- | --- |
| 嵌套圆角与连续几何关系 | 分析父子容器内缩、圆角、边框和视觉连续性 | 可测量 + 启发式 |
| 字号、边框、间距、组件一致性 | 对照项目 Token、同角色组件和设计系统分析偏离 | 客观比较 + 建议 |
| 内容优先与视觉层级 | 标题/正文/行动按钮/装饰的视觉竞争与主次关系 | 规则 + 人工/模型建议 |
| AI 模板化特征 | 检查装饰密度、无依据标签、重复卡片、强调色泛滥 | **仅建议，不判来源** |
| 可解释的设计原则 | 建立规则 ID、证据、适用场景、例外与修复策略 | 规则知识体系 |
| 高质量组件复用 | 对问题图层推荐已有 Token、组件/变体或本地组件库 | 优先本地复用 |
| 中英文混排与字体 | 字体回退、中文行高、文字膨胀、标点与换行检查 | 浏览器实测 + 建议 |
| 图标和交互细节 | 图标统一、语义状态、键盘焦点与热区检查 | 实测 + 建议 |

## 3. 信息架构与用户工作流

### 3.1 质量检查入口（DQ-001）

在现有“检查”区域增加“设计质量”分类，避免另建与浏览器几何检查冲突的第二套审计系统：

1. 用户选择 **当前元素 / 选区 / 当前画板 / 整个项目**。
2. 可选审查维度：布局几何、字体排版、色彩与品牌、组件一致性、交互可用性、响应式与多语言、模板化风险。
3. 审查上下文：实际画板宽度、主题、控件状态、语言、设计简报约束与选中的 profile。未明确选择时沿用工程现状。
4. 先跑**纯本地、可复现的确定性检查**；不自动发起模型调用。
5. 输出按“需修复 / 需复核 / 可优化”分组的 findings；每条含规则、位置、证据、适用条件、为什么、修复建议及影响范围。
6. 点击 finding 高亮实际画板/图层，打开 Inspector 对应属性；组件源投影须映射回可编辑的真实持久化节点或实例入口，不允许拿渲染副本 ID 当 Patch 目标。
7. 检查结果可导出为只读报告，工程/主题/断点/状态变化后显式标记**已过期**；重新执行才能称为当前结果。

“找不到真实 DOM / 内容被遮挡 / 对比度被透明叠加影响 / 目标是外部资源”时应报告证据不足，禁止伪造通过。

### 3.2 智能精修入口（DQ-002）

选中具体问题或画板，点击“提出精修方案”，展示差异和可能的副作用；只有明确审批后才写项目。先提供无需模型的确定性修复建议，再扩展用户授权的 AI 精修。

用户可以**逐条接受/拒绝**，查看影响节点、Token 引用范围、主题和多断点前后变化；支持 Undo/Redo。拒绝、取消、旧哈希冲突或失败均保持原工程不变。

### 3.3 风格和品牌上下文（DQ-003）

默认使用设计简报与当前 Tokens / 字族 / 组件系统作为首要约束。可选内容优先、产品展示、高密度等现有 profile；未来允许项目自定义例外。没有品牌约束时，建议不能伪装成“必须遵守”的硬规则。锁定层、用户人工改动和非目标区域始终受到保护。

## 4. 质量规则体系（计划实现）

下面规则均需具有稳定 ID、适用/不适用条件、证据字段、严重程度、可修复性和回归夹具。规则阈值必须可配置且标注是否来自平台指南、项目 Token 或启发式，不将偏好当作国际标准。

### A. Geometry & Spacing（QG）

- **QG-01 嵌套圆角**：只有在父子同形容器、近似等距内缩且参与实际绘制时，提示内部半径可考虑接近 max(0, 外半径 − 内缩距离)；需考虑边框和相邻圆弧，明确这只是启发式，非强制约束。任意不规则遮罩、图标、故意对比的圆角不适用。
- **QG-02 对齐和间距**：从同角色相邻元素及 Token 推断间距规律，检测可验证的偏差；对光学对齐、瀑布流、艺术排版仅提出建议。
- **QG-03 边框与层级**：同级卡片/输入控件的边框粗细、颜色角色、阴影层级和圆角一致性；不能仅凭数值不同认定错误。
- **QG-04 图标细节**：同角色图标的视觉尺寸、线宽、基线与安全留白；没有可信的真实轮廓数据时只给弱提示。

### B. Typography & Localization（QT）

- **QT-01 字号与文字层级**：检查同语义文本的字号、字重、行高、间距是否偏离项目排版 Token；考虑标题层级和中文字符密度。
- **QT-02 实际文字布局**：复用浏览器测量检查裁切、遮挡、换行、行盒、溢出和字号过小；不可用静态坐标代替真实浏览器结果。
- **QT-03 CJK / Latin 混排**：字体回退、中文/英文字形高度与标点换行、长数字/货币、翻译引起的膨胀；支持基准文本及 +30% 压力场景，明确压力测试不是实际翻译质量保证。
- **QT-04 动态内容**：多行昵称、极长按钮文本、金额与关卡数值上界、空态/错误态文本；与响应式测试联动。

### C. Color & Tokens（QC）

- **QC-01 品牌角色色**：主色、强调色、背景、文本、危险/成功等语义 Token 的使用一致性。品牌主色应优先保留，不可因“太亮”而擅自压暗。
- **QC-02 对比度**：区分静态可计算与浏览器叠色/真实背景不可确定的场景；文字与交互控件仅在证据充分时给出相应阈值判断。不能以简单静态检查宣称全面符合 WCAG。
- **QC-03 装饰与色彩密度**：同屏颜色角色过多、过量渐变/边框/卡片等仅作为可解释的设计建议；允许品牌或题材豁免。

### D. Interaction & Accessibility（QI）

- **QI-01 可点击热区**：移动端 44×44 CSS px 作为默认设计启发式，支持平台特定例外；与现有 TOUCH_TARGET 测量结果合并去重。
- **QI-02 状态完整性**：检查已建模按钮/input 的 Hover/Active/Focus/Error/Disabled/Loading 是否保持可识别、焦点可见，不能只通过颜色传达错误信息。
- **QI-03 语义反馈**：检查按钮、状态文本、图标、loading 提示的语义一致性；未实现真实业务事件状态机前，不声称实际表单或导航可用。
- **QI-04 Reduced Motion 与键盘**：优先利用现有控件语义和浏览器实测；对无法模拟的真机交互明确列出未验证。

### E. Responsive & Domain（QR）

- **QR-01 断点**：在 390/768/1440 等代表性宽度及用户实际断点测量溢出、视觉错位和内容撑开；不是所有项目强制必须拥有三个固定断点。
- **QR-02 产品场景**：支持 App/H5 游戏/横竖屏 HUD/语聊房/后台高密度布局的不同检查 profile；保留安全区、动态金币/钻石/比分/昵称等测试数据的可配置性。
- **QR-03 状态与主题矩阵**：至少能够区分普通/暗色主题和关键控件状态，防止基础状态通过而 Focus/Error 下视觉失效。

### F. Template Pattern Advisor（QP，原讨论称“AI Slop Detector”）

- **QP-01** 识别“模式化风险”，而非猜测图像是否由 AI 创作。参考模式：无目的紫色渐变、重复内容卡片、营销标签泛滥、孤立的边框/阴影、视觉重点过多、字体或图标语言不统一。
- **QP-02** 每条只作为 suggestion/advisory，必须描述可观察证据和改进理由，并可忽略/标记“符合品牌意图”。紫色渐变或多标签单独出现不构成缺陷。
- **QP-03** 必须先检查项目 profile、Token、设计简报和组件角色；不能硬编码“只允许黑白灰”“禁渐变”“禁某种字体”等审美铁律。

### G. Visual AI Reviewer（QA，可选）

- **QA-01** 用户主动选择接入的模型与审查范围（BYOK，可换模型）。提供截图、布局上下文及经过用户许可的数据最小集；不能默默上传完整项目、私有素材或 API 密钥。
- **QA-02** 模型输出结构化意见：观察事实、推测、改法、证据与不确定性。所有意见均为待审建议；模型不可直接写项目或执行任意命令。
- **QA-03** 设计评价需识别审美偏好分歧，支持用户拒绝/固定风格约束，不能把模型打分当作绝对质量。

### H. Auto Polish（AP）

- **AP-01** “局部优先”：遵循选区/节点/画板范围和现有 Patch 白名单；优先在原节点 set 更新，不删除重建无关内容。
- **AP-02** “品牌不漂移”：缺少额外授权，禁止全局换主题、覆盖 Tokens、替换字体/组件源、删除人工文字或扩展到别的画板。
- **AP-03** “变更可审核”：每条建议都展示 AST 字段 Diff、影响节点、引用范围，后期增加真实截图并排对比；用户逐项接受/拒绝。
- **AP-04** “安全且可撤销”：提交前检查 baseHash、锁定/引用关系、数据预算与完整校验；不合法、过期、影响范围扩大、证据不足均拒绝；应用后重新检查并保留 Undo。
- **AP-05** “闭环而非自动覆盖”：AI → 最小 Patch → 审批 → 浏览器复检 → 告知剩余缺陷，默认不自主循环覆盖设计稿。

## 5. 可解释质量报告协议（DQ-004，拟议）

建议新建只读质量报告 designforge.quality-report v1；**目前尚无实现，不是项目格式 v1 或 Patch v1 的既有字段**。至少包含：

- reportVersion、ruleSetVersion、generatedAt、projectHash、范围 scope、所用浏览器/渲染环境与审查上下文（width/theme/locale/state）。
- findings：稳定规则 ID、severity（error/warning/suggestion）、boardId、真实 nodeId、可选组件 sourceId/实例来源、证据 measurements、解释、适用例外、影响范围、可修复等级（safe/review/manual）、数据来源（static/browser/model）。
- 限额、截断状态与 limitations；不可验证项目必须带未测原因，不得默认为 0 问题或“合格”。
- findings 的内容属**不可信数据**；报告只能显示/导出，不能含可执行脚本、外部自动请求或模型隐式指令。
- 同一类问题由 core 静态审计和浏览器测量同时发现时按规则/节点/上下文归并，不重复计数。
- 未实施“统一质量分”之前不对外输出无来源的数值总分；未来若加入评分需公开权重和证据覆盖率。

## 6. 安全、性能、隐私与兼容约束

1. 复用 src/core.mjs 的静态校验、src/browser-audit.mjs 的实测、现有断点/状态/Design Tokens/组件投影以及 designforge.patch v1（baseHash、白名单、原子应用、人工确认）。不要建立与之矛盾的平行编辑协议。
2. 所有只读检查禁止修改 project.updatedAt、撤销栈、localStorage 或用户选区；离屏测量须在取消/异常情况下清理。
3. 规则数量、节点数、候选对比较和模型调用均受预算限制；超限报告 truncated，不能以“没有发现”代替未检查。
4. 模型提供商不可硬编码；本地机密保存在安全后端，不进入设计文件、浏览器前端、只读报告或日志。默认离线/无模型可运行。
5. 用户批准之前不得向外部服务发送画板截图、评论、个人内容或资源。远程审查要有范围预览和明确授权。
6. 保持旧 Orbit 3 画板/170 节点与所有正式工程往返兼容；不默默迁移字段，不改出站 HTML/ZIP 的现有语义。
7. 所有客观与审美判断需标注边界；保留项目品牌色、合法创作差异及人为例外，不因为提高“评分”牺牲用户的设计目标。

## 7. 验收标准（未达到前不得标记完成）

- **规则可靠性**：每个规则有正例、反例和例外夹具。错误能定位到真实编辑对象与上下文；无 DOM / 遮挡 / 透明叠色时能正确说明不确定性。
- **零无关误改**：预设多画板、组件实例、共享 Token、锁定层和人工覆盖夹具；无授权的节点/Token 变化数必须为 0。
- **响应式覆盖**：代表性 390/768/1440 宽度，加上实际项目断点；亮/暗主题、关键控件状态、中文/英文与动态长文本分别检测。
- **补丁安全**：旧 baseHash、锁定元素、引用破坏、非法操作和超预算必拒绝，失败不写项目；合法局部变更可撤销且复跑质量检查。
- **视觉证据**：真实 Chrome/Firefox/WebKit 检查范围和截图证据可追溯；像素基准不能无审阅自动更新，平台/字体不一致需注明。真机未测不可称已测。
- **可解释性**：报告可以导出，能区分确定事实与审美建议，用户可忽略不适用规则；不支持时明确未实现。
- **AI 评测**：M2 上线前进行固定任务集盲测，记录需求符合度、设计一致性、无关元素误改率、人工审批负担与耗时；不能仅凭模型口碑宣布超越竞品。

## 8. 分阶段关系

- **M1-Q（P0）**：确定性规则、质量报告协议、去重/过期、问题定位、排版与几何实测；不需要 API Key。
- **M1.5（P1）**：模板化风险建议、局部修复建议、质量面板和选择性应用的完整体验；不强依赖模型。
- **M2（P2）**：可授权的多模型视觉审查、图形 Diff、Auto Polish 最小 Patch 与多断点复验。
- **持续演进（P3）**：可版本化设计知识库/Skill、项目/领域检查 profile、复用与规则评测数据集。
