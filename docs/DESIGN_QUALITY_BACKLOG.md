# DesignForge Studio｜设计质量与智能精修实施清单

> 详细交互、规则及安全边界：[DESIGN_QUALITY_PRD.md](DESIGN_QUALITY_PRD.md)  
> 工作原则：复用现有 M1 审计、设计系统、Agent Patch、浏览器 CI；新功能必须有实际用例和对应截图/日志，不能把规划写成已交付。

## 依赖基线（已存在，不计入本需求交付）

- 树状 AST、Flex/Grid、Tokens/alias/主题、组件变体/实例、断点、富文本与状态模型。
- core.mjs 的结构/基础审计，browser-audit.mjs 的浏览器几何/裁切/触控检测。
- readonly 的 designforge.context / design brief，旧 designforge.patch v1、baseHash、审批、撤销及浏览器 CI。
- 上述基础不意味着设计审美检查、AI 视觉评估或 Auto Polish 已实现。

## 当前已接通的切片

[本地设计质量报告](QUALITY_REPORT.md)接入现有检查面板和几何/文字测量。提供报告、过期保护、三种范围、筛选/定位及八项规则。下列任务包含更广范围，暂不整项勾选；同角色一致性、字形回退、状态完整性与主题/断点矩阵尚未完成。

## P0 · 确定性 Design Quality Engine（优先接续 M1）

- [ ] **DQ-P0-01｜规则/报告基础协议**：创建 quality-core 规则注册、ID/严重度/适用条件/例外/证据 schema 与只读 quality-report；项目哈希、width/theme/state/locale 上下文和“结果过期”机制。**验收**：schema 校验、导出、预算截断与过期单测；只读运行不修改工程/历史。
- [ ] **DQ-P0-02｜几何规则**：嵌套圆角启发式、同角色间距/对齐/边框一致性。**验收**：不同 inset、边框厚度、嵌套容器和有意非同心布局的正反例；只给非破坏性建议。
- [ ] **DQ-P0-03｜中英文排版**：字体层级、实际行盒/截断、字体回退、CJK/Latin 混排、长数字/金额和 +30% 文本膨胀场景。**验收**：真实浏览器测量，能区分可计算事实/未覆盖场景。
- [ ] **DQ-P0-04｜色彩/状态/热区规则**：主色与语义 Token 一致性、可证明对比度、Focus/Error/Disabled/Loading 状态、44px 热区启发式。**验收**：复用现有 findings 并去重；透明背景/禁用控件不虚报 WCAG。
- [ ] **DQ-P0-05｜质量面板 MVP**：按规则/严重度/范围筛选，点击高亮画板和真实可编辑图层，展示证据、说明和“无法判断”的原因。**验收**：选区/整板/整项目，锁定/组件实例/断点来源正确，Chrome/Firefox/WebKit E2E。
- [ ] **DQ-P0-06｜回归数据集**：Orbit、Studio、Launch、App、后台和游戏 HUD 的可重复夹具，覆盖 390/768/1440、亮/暗、中文/英文及长文本。**验收**：每条质量规则有命中/不命中/例外样例；现有导入导出与测试不退化。

**P0 阶段门槛**：无需任何模型密钥即可生成可解释的本地质量报告；不能把所有“建议”显示为客观违规；检查不改稿。

## P1 · 可操作的设计改进（M1.5 / M2 前置）

- [ ] **DQ-P1-01｜模板化风险顾问**：重复卡片、标签密度、无目的渐变、过量边框/阴影、图标不一致等软规则。**验收**：项目 profile / 品牌约束例外，不能据此断言“由 AI 生成”。
- [ ] **DQ-P1-02｜组件与 Token 复用推荐**：优先建议项目已有组件、变体和语义色；分析全局 Token 改动影响。**验收**：不会为同一角色创建无必要的重复定义；涉及共享定义时默认只建议不自动写。
- [ ] **DQ-P1-03｜规则驱动安全建议**：为确定性规则输出有限范围修复提案；关联 Patch 校验、冲突/锁保护。**验收**：旧哈希、锁定、非目标图层/设计系统变化均拒绝；可单步 Undo。
- [ ] **DQ-P1-04｜交互审批体验**：建议与证据并排、分组/逐项接纳、撤销及结果重检。**验收**：取消、拒绝、半数接纳、过期报告、冲突和错误都不能修改用户未批准内容。

**P1 阶段门槛**：设计师能够查到具体问题、理解其依据、在不改坏其他元素的情况下修正，并重新验证。

## P2 · 授权的 Visual AI Reviewer + Auto Polish（M2）

- [ ] **DQ-P2-01｜BYOK 多模型审查适配**：不硬编码模型商、最小化截图/上下文、显式权限与成本提示、只读结构化建议。**验收**：无授权零外发；错误/超时/额度耗尽不丢设计；不泄露密钥。
- [ ] **DQ-P2-02｜视觉审美建议**：将图像观察与可验证规则分开；输出置信/不确定性、依据和可否局部修复。**验收**：允许用户拒绝审美建议，不能用风格喜好覆盖品牌约束。
- [ ] **DQ-P2-03｜Auto Polish 最小 Patch**：选区限定、白名单修改、保留人工编辑、引用依赖分析、逐项审批与版本冲突拒绝。**验收**：多板/组件/共享 Token 的无关节点误改为零；完整 Patch 验证通过。
- [ ] **DQ-P2-04｜可视化 Diff 与复审**：原稿/修订稿并排截图，标注改动和残留问题，跨断点/主题/状态回归；失败回滚。**验收**：浏览器真实渲染与用户确认；不能用截图 Diff 替代数据校验。
- [ ] **DQ-P2-05｜固定任务盲测**：至少包含移动 App、后台、游戏 HUD、语聊/聊天、国际化长文本；对照同输入/相同模型或注明条件差异。**验收**：记录符合度、一致性、无关误改、审批数量、完成时间与失败案例。

**P2 阶段门槛**：用户可以授权模型查阅指定 UI 并获得可审核的局部精修；无未授权外发/未批准修改；有真实浏览器复验。

## P3 · 设计知识系统与行业能力（持续）

- [ ] **DQ-P3-01｜规则知识库与 Skill**：每条规则保存适用条件、反例、解释、有限修复手段、版本；Skill 可依据规则提出方案，但不扩大工具权限。
- [ ] **DQ-P3-02｜领域 profile**：移动游戏/横竖屏 HUD、语聊房、输入法、营销页和后台；确保例外来自用户需求，避免一套规则压平所有美术题材。
- [ ] **DQ-P3-03｜评估与治理**：误报/漏报回放、版本回归、用户排除例外、可选质量覆盖率统计；确保项目升级后规则结果可追踪。

## 工程落点建议（仅设计，不代表已有模块）

| 现有工程入口 | 计划改动方向 |
| --- | --- |
| src/core.mjs | 接入纯函数规则汇总，不修改旧 validate/audit 语义 |

| 现有 Patch / 历史模块 | 合并安全修改、局部 Undo/Redo、Diff 与冲突处理 |
| tests/*.test.mjs + tests/browser | 规则夹具、浏览器检测、局部修改、负例、截图证据 |
| skills/designforge/SKILL.md | **在 P3 实现之后**增补真实可执行的质量工作流；规划阶段不要假装 Skill 已支持 |

## 研发禁令与完成定义

- 不能只更新 README 或仅添加 Prompt 就把引擎标成完成；每项完成需要代码、测试、报告示例和验证记录。
- 不得自动降低品牌识别色、乱换字体、推倒重排无关节点；不得把“AI 模板化倾向”当作来源鉴定。
- 不得绕过人工 Patch 审批、项目哈希、组件锁及本地优先的数据界限。
- 不合并 main、不部署网站、不操作用户设备，除非收到独立明确指令。
- Issue 勾选、产品代码版本与真实 CI 状态必须一致；新增失败和已知边界写入 KNOWN_ISSUES / VALIDATION。
