# DesignForge 开发路线与验收

路线以可用能力为准，不以具体日期承诺交付。每个阶段都要求代码、文档、测试同步完成。不要把前沿方向描述成已实现功能。

## M0：原创闭环验证（本版已交付）

- [x] 可导入/导出的结构化设计项目格式（JSON AST，v1）。
- [x] 多画板、基本图层、基础几何/文字/Token 属性修改。
- [x] 本地自动保存、Undo/Redo、注释锚点、静态质量检查。
- [x] HTML/ZIP 导出、项目 CLI、Agent Skill、补丁白名单与人工审批。
- [x] 3 块内置画板，170 个示例节点，自动单元测试。
- [x] 后续 M1 开发中通过 GitHub Actions 真实 Chrome 补齐 M0 编辑/导出回归与截图；范围和剩余缺口见 VALIDATION.md。

### M0 完成定义

在支持 Node 20+ 的本地电脑上运行 `npm start`，可以编辑演示画板、导出 JSON/HTML ZIP；CLI 可验证、审计项目；一个带正确快照哈希的 Patch 可被审阅后应用，错误旧哈希会拒绝。真实浏览器交互正确性需额外验收。

## M1：可用于认真设计的画板核心

- 可嵌套 Layer AST，Frame / Group / Component / Instance / Variant。
- Auto Layout：方向、间距、内边距、对齐、文字撑开、约束与响应式断点。
- 富文本、多语言文本膨胀预检、自定义字体、图片素材、矢量图形。
- 画布：智能吸附、标尺/参考线、多选对齐与分布、缩放鼠标手势、自动版面整理。
- 更严谨的节点级修订历史、Undo/Redo、文件版本导入迁移。
- Playwright/Chromium 自动检查：溢出、截断、颜色对比、触控目标、可用性与截图 Diff。

**可验收指标：** 给同一产品设计 Desktop/Mobile 两个断点，内容更换仍无关键布局溢出；覆盖核心编辑动作的 E2E 测试通过；至少 10 个正式设计样例可往返导入导出且无丢字段。

## M2：真正一体化的 AI 设计工作流

- BYOK 模型网关（用户可选供应商，凭据仅服务于本地安全后端，不写入画板/前端文件）。
- 多阶段 Agent：Brief → 研究意图 → 布局方案 → 组件生成 → 渲染反馈 → QA → Patch。
- 选区、元素、局部区域与标注上下文直达 Agent；支持“只改这个按钮”“保留人工编辑”。
- 可视化修订审阅：字段级与截图级并排对比，用户逐项接受/拒绝。
- 冲突合并：3-way node merge、锁定区域、影响范围分析、审计报告与重现路径。
- Skill 适配 Codex / Claude Code / Cursor / 其他遵循规范的 Agent。

**可验收指标：** 20 套任务的盲测记录“需求符合度、错误率、设计一致性、无关元素误改率、完成编辑时长”。在不降低完成度的前提下，将**无关元素误改率**作为首要优化指标，而不是靠截图主观宣称超过竞品。

## M3：研发交付、行业专用与团队协作

- CSS variables + React/Vue 可维护代码输出；双向 diff，自动 PR 附带截图和运行检查。
- 设计系统库：跨项目 Token/组件版本、依赖关系、回滚、授权许可标记。
- 原型 Flow：交互状态、导航/转场、变量、错误/空态、事件模拟。
- Figma/HTML/现有 GitHub 前端导入及可编辑结构解析，明确保留程度。
- 多人协作、冲突处理、文件化团队工作区、Cloudflare Pages 可选预览（用户**显式授权**后才部署）。
- 游戏 UI 特有能力：横竖屏/安全区/刘海、直播间 HUD、多尺寸 H5、数值动态内容、动画状态图、低性能设备预算。

**可验收指标：** 用真实的输入法/H5 游戏/管理后台需求跑完整设计到代码交付；通过 CI 可读性、可维护性、功能回归与性能检查。

## 与竞品的比较原则

每次比较标明版本、样本任务、同一输入、硬件/模型、可量化维度。BaoCut 中已存在但未公开启用的模块，不凭源码目录猜测线上现状；DesignForge 的 Roadmap 事项在验收前一律视为未完成。
